# Субтитры: Plus

Плагин `subtitles-plus.js` (ES5, без сборки) добавляет на панель встроенного плеера кнопку **«С+»** рядом
со стандартной «С». В ней есть пункт «Отключить» (выбран по умолчанию) и список субтитров. Дорожку, выбранную
в «С+», плагин рисует в своём слое и по своим настройкам. Встроенные настройки субтитров Lampa (размер,
обводка, подложка, сдвиг времени) на этот слой не влияют.

Настройки находятся в шестерёнке плеера, в пункте **«Субтитры: Plus»** сразу после встроенного «Субтитры».

Вшитые субтитры торрентов на LG webOS телевизор рисует сам, и их текст недоступен Lampa. Для них есть
**прокси на ТВ** (каталог [`subtitles-plus-proxy`](../subtitles-plus-proxy)): видео идёт через него, а он
по пути забирает из MKV строки субтитров. Лишнего трафика нет: прокси разбирает только те байты, которые
плеер и так скачивает.

## Установка плагина

**Настройки → Расширения → Добавить плагин**, адрес
`https://etix-git.github.io/lampa-plugins/subtitles-plus.js`, затем перезапустите Lampa.

## Кнопка «С+»

- **Отключить** — субтитры не показываются (и у Lampa, и у ТВ). На webOS под этим пунктом виден статус
  прокси для текущего видео: «видео идёт через прокси», «прокси работает, но это видео идёт напрямую»
  (не торрент или видео открыто до старта прокси) или «прокси не найден».
- **Дорожки** — у каждой подписано, откуда берётся текст: «из файла → Plus», «внешний файл → Plus»,
  «дорожка видео → Plus», «Lampa → Plus» или «рисует ТВ».

Выбор запоминается: в следующей серии или фильме плагин сам включит дорожку с тем же языком и названием,
а если их нет, то с тем же языком. Если выбрано «Отключить», дальше тоже будет выключено.

Если выбрать дорожку в стандартной «С», субтитры снова показывает Lampa, а «С+» переходит в «Отключить».

## Настройки (шестерёнка → «Субтитры: Plus»)

| Пункт | Значения (по умолчанию) |
|---|---|
| Заменить стандартные субтитры | прячет кнопку «С», остаётся только «С+» (выкл) |
| Прокси для торрентов (webOS) | использовать прокси на ТВ, если он запущен (вкл); в подписи видно, найден ли прокси |
| Размер | 50–250 % (100 % — как обычный размер Lampa) |
| Цвет текста | белый, жёлтый, зелёный, голубой, синий, красный, пурпурный, серый, чёрный (белый) |
| Прозрачность | 100–25 % (100 %) |
| По вертикали | снизу, посередине, сверху (снизу) |
| Отступ от края | 0–30 % высоты экрана (5 %) |
| По горизонтали | слева, по центру, справа (по центру) |
| Задержка | от −10 до +10 с с шагом от 0.1 с (0); «+» значит позже, «−» раньше |
| Подложка | нет, чёрная, серая, белая, синяя (нет) |
| Прозрачность подложки | 10–100 % (55 %) |
| Обрамление / тень | нет, тонкий контур, толстый контур, тень, приподнятый, утопленный, свечение (тонкий контур) |
| Цвет обрамления | чёрный, серый, белый (чёрный) |
| Сбросить | возвращает оформление по умолчанию; «Заменить» и «Прокси» не меняет |

Пока открыто меню, на экране виден пример субтитров. Когда фокус переходит по значениям, вид меняется
сразу, а сохраняется только по ОК. «Назад» отменяет изменение. Задержку видно сразу на настоящих субтитрах.

## Откуда берётся текст

| Источник | Когда | Задержка |
|---|---|---|
| **Из файла** (прокси) | вшитые текстовые дорожки MKV/WebM из торрента на webOS (SRT, ASS/SSA, WebVTT) | «+» любая, «−» в пределах того, что плеер уже подкачал (запас виден в пункте «Задержка») |
| **Внешний файл** | внешние srt/vtt, которые передал источник; плагин сам загружает и разбирает файл | в обе стороны |
| **Дорожка видео** | нативные дорожки `<video>` (`textTracks` с cues) | в обе стороны |
| **Lampa** | остальное, что рисует Lampa (HLS.js, Tizen AVPlay и т. п.): плагин повторяет её текст | только «+» |
| **Рисует ТВ** | вшитые дорожки на webOS без прокси, а также картинки (PGS, VobSub) | экспериментально, см. ниже |

### Дорожки, которые рисует ТВ

Плагин передаёт медиасервису webOS то, что он умеет: размер (5 ступеней), цвет (белый, жёлтый, красный,
зелёный, синий, чёрный; остальные — ближайший), прозрачность текста, подложку и её прозрачность, положение
по вертикали. Задержка передаётся методом `setSubtitleSync`; если ТВ его не знает, появится сообщение.
«По горизонтали» и обрамление для таких дорожек не работают, в меню это подписано.

Соответствие цветов и положений медиасервиса подобрано по косвенным данным, на конкретном ТВ может отличаться.

## Прокси на ТВ (webOS)

Нужен LG webOS с root (Homebrew Channel). Прокси написан на Node.js, который уже встроен в webOS, и
ничего доустанавливать не нужно. Слушает только `127.0.0.1:8095`.

Есть вторая версия прокси, на Go: [`subtitles-plus-proxy-go`](../subtitles-plus-proxy-go/README.md). Это одна
программа без зависимостей с тем же API, нагрузка на процессор примерно втрое меньше. Она ставится вместо
Node.js-версии командой `make deploy TV=<ip>`, вернуться можно установкой Node.js-версии.

### Установка

С компьютера, из корня репозитория (`<ip>` — адрес ТВ):

```sh
tar -cf - subtitles-plus-proxy | ssh root@<ip> 'tar -C /tmp -xf - && sh /tmp/subtitles-plus-proxy/install.sh'
```

`install.sh` копирует файлы в `/media/developer/apps/var/lib/subsplus/` и ставит автозапуск: симлинк
`/var/lib/webosbrew/init.d/70-subsplus` → `/media/developer/apps/var/lib/subsplus/subsplus.sh`. Затем запускает прокси, проверяет
`/health` и печатает версию, папку, адрес, PID и автозапуск. Прокси перезапускается сам, если упадёт; лог в
`/tmp/subsplus.log`.

После установки откройте в шестерёнке плеера «Субтитры: Plus»: у пункта «Прокси для торрентов» должно быть
«работает». Прокси подхватывается для следующего запущенного торрента.

Удаление: `ssh root@<ip> sh /media/developer/apps/var/lib/subsplus/install.sh --uninstall`.

### Проверка нагрузки

Прокси пропускает через себя весь видеопоток, поэтому на слабых ТВ стоит проверить его на тяжёлом файле
(4K-ремукс). Возьмите торрент, который уже хорошо скачан в TorrServer, и адрес потока, который играет Lampa:

```sh
ssh root@<ip> "sh /media/developer/apps/var/lib/subsplus/bench.sh 'http://<torrserver>:8090/stream/Movie.mkv?link=<hash>&index=1&play' 400"
```

Скрипт читает 400 МБ напрямую, через прокси и снова напрямую, и показывает скорость, загрузку процессора
и память `node`. Скорость через прокси должна быть заметно выше битрейта фильма (минимум в 1.5 раза),
а загрузка процессора — умеренной (до ~25 % одного ядра на 4K).

### Как это устроено

- Плагин подменяет адрес торрент-потока (`…/stream/…?link=…`) на `http://127.0.0.1:8095/v/<имя>?u=<адрес>`,
  только если прокси отвечает. Иначе видео идёт напрямую, как без плагина.
- Прокси пересылает запросы плеера (включая Range) в TorrServer и отдаёт ответ без изменений. По пути он
  разбирает Matroska: читает список дорожек и берёт блоки текстовых субтитров; видео и аудио пропускает,
  не копируя. После перемотки находит ближайший кластер и продолжает.
- Плагин раз в секунду забирает у прокси строки выбранной дорожки вокруг текущего времени.
- Если прокси перестал отвечать, через 10 с плагин отдаёт ту же дорожку телевизору и сообщает об этом.

API прокси: `GET /health`, `GET|HEAD /v/<имя>?u=<url>`, `GET /tracks?u=<url>`,
`GET /subs?u=<url>&track=<N>&from=<с>&to=<с>`.

### Тесты прокси

`subtitles-plus-proxy/test`: генератор синтетических MKV, тест разбора и сквозной тест (заглушка TorrServer →
прокси). Запуск на той же версии Node, что на ТВ:

```sh
python3 subtitles-plus-proxy/test/gen_mkv.py /tmp/a.mkv
python3 subtitles-plus-proxy/test/gen_mkv.py /tmp/c.mkv --unknown-clusters --seconds 40 --seed 2
docker run --rm -u $(id -u):$(id -g) -v $PWD:$PWD -v /tmp:/tmp -w $PWD node:12.21.0 \
  sh -c 'node subtitles-plus-proxy/test/test_parser.js subtitles-plus-proxy/server.js /tmp/a.mkv /tmp/c.mkv &&
         node subtitles-plus-proxy/test/e2e.js subtitles-plus-proxy/server.js /tmp/a.mkv'
```

`subtitles-plus-proxy/test/plugin_smoke.js` проверяет сам плагин в jsdom с настоящим прокси и заглушкой
TorrServer: подмену адреса, кнопку «С+», дорожки из файла и от ТВ, задержку, защиту от повторного включения
субтитров ТВ, память и отказ прокси. Нужны `jsdom` и `jquery` (путь к их `node_modules` — в `SMOKE_MODULES`),
прокси передаётся командой: Go-сборка или `server.js`.

```sh
docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp -e SMOKE_MODULES=/tmp/smoke/node_modules \
  -v $PWD:$PWD -v /tmp:/tmp -w $PWD node:24.20.0 \
  node subtitles-plus-proxy/test/plugin_smoke.js subtitles-plus.js /tmp/a.mkv subtitles-plus-proxy-go/dist/subsplus-proxy-linux-amd64
```

## Ограничения

- Прокси работает только на webOS с root и только для торрентов через TorrServer.
- Из файла читаются только текстовые дорожки MKV/WebM. Вшитые субтитры MP4, TS, AVI и картинки (PGS, VobSub)
  показывает ТВ с урезанными настройками.
- Оформление ASS (позиции, караоке, надписи) не сохраняется: строки показываются обычным текстом.
- После перемотки строки до первого кластера на новом месте (обычно 1–2 с) могут не показаться.
- HTML-теги из srt (`<i>`, `<b>`, `<font color>`) сохраняются, поэтому цвет из `<font color>` имеет приоритет.
- В мобильном меню «…» кнопки «С+» нет.
